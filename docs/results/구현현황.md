# ATM 앱 v1.0.0 구현 현황

기준 설계: 통합 상세설계 v3.0.0 / 작성일: 2026-11-18

Python 3.13과 Tkinter·ttk로 로컬 데스크톱 앱을 구현했다. 제품 실행에는 외부 패키지·은행 서버·DB가 필요하지 않다. 원래의 9개 클래스와 44개 설계 메소드를 모두 구현했다.

## 구현 표기 대응

문서의 String/int/boolean/void/null은 Python의 str/int/bool/None/None으로 구현했다. 계좌번호·입력값 등의 속성 이름은 Python 관례의 snake_case를 사용한다. 예를 들어 `accountNumber→account_number`, `shownBalance→shown_balance`, `failedCount→failed_count`, `selectedMenu→selected_menu`, `amountText→amount_text`, `targetAccountNumber→target_account_number`, `depositLimit→deposit_limit`로 대응한다.

AccountManager의 계좌 컬렉션은 개념 설계상 목록이며, 외부에 노출하는 `accounts`는 읽기 전용 tuple이다. 호출자가 목록을 바꾸어 내부 계좌 검색 인덱스와 어긋나지 않게 했다. VirtualAccount의 계좌번호·잔액·횟수·차단 속성은 읽기 전용 property이며 변경은 명시된 도메인 메소드를 거친다.

## 동작

- ASCII 숫자 12자리 계좌번호와 4자리 PIN으로 로그인한다. PIN의 선행 0을 보존하고 화면에서는 마스킹한다.
- 형식 오류·미등록 계좌는 횟수를 늘리지 않는다. 등록 계좌의 PIN 불일치만 증가시키며 5회째 차단한다. 정상 인증은 오류 횟수를 0으로 바꾸고 차단 계좌는 정상 PIN도 거절한다.
- 입금은 양의 정수·100만 원 한도·잔액 상한을, 출금은 양의 정수·1만 원 단위·100만 원 한도·실제 잔액을 검사한다.
- 가상 이체는 대상 12자리·본인 제외·양의 정수·실제 잔액을 확인한다. 별도 100만 원 이체 한도를 두지 않으며 수신 계좌는 생성·변경하지 않는다.
- 처리 중 확인 버튼과 취소를 잠그고, 처리 플래그·입력 화면 단계·요청 세대로 같은 요청의 재진입과 이전 콜백 재생을 막는다.
- 결과 화면에서 계속 이용과 종료를 선택한다. 출금 성공 시에는 명세표 예·아니오 안내를 먼저 제공하며 실제 인쇄는 하지 않는다.
- 종료는 숨겨진 입력 위젯과 표시 자료까지 지운다. 처리 중 종료·창 닫기는 이미 접수한 거래가 끝난 뒤 정리한다.
- 로그아웃은 실행 중 잔액·차단을 보존한다. 새 프로세스는 시드 초기 상태를 다시 읽으며 시드 파일을 수정하지 않는다.

## 실행과 검증

프로젝트 루트에서 `python run_atm.py` 또는 Windows의 `ATM_실행.pyw`를 사용한다. 별도 시드는 `python run_atm.py --seed 경로`로 지정한다. 초기 자료가 잘못되면 거래 화면을 제공하지 않는다. `--check`를 함께 사용하면 GUI 없이 초기 자료만 검사한다. `python -m atm_app`은 가상환경에서 `pip install -e .`로 설치한 뒤 사용할 수 있다.

자동 검증은 [테스트결과.md](테스트결과.md)와 [JSON 상세 기록](테스트결과.json)을 참조한다. `python -X utf8 tools/run_tests.py`로 재실행한다. 단위·서비스·실제 Tk 이벤트 루프·서브프로세스 재시작·최소 창 크기 배치를 검증한다. [설계 계약 검사](../../tools/verify_implementation.py)는 44개 메소드의 존재와 매개변수 수, 관련 파일과 문서 링크를 확인한다.

## 범위와 남은 확인

실제 금융 거래, 암호화·실물 현금·프린터·다중 사용자·영속 저장은 설계 범위 밖이다. 가상 PIN을 실제 계좌에 사용하지 않는다. 외부 은행 송금이나 재시작 후 잔액 유지 기능이 있는 것으로 해석하지 않는다.

컴퓨터 화면 제어 연결이 작동하지 않아 스크린샷 육안 검토는 미실시다. 현재 검증은 자동 시험 및 Tk 위젯 배치 확인까지이며, 다른 Windows 배율·글꼴 환경은 사용 환경에서 확인할 수 있다. 별도 실행 파일(EXE) 패키징은 포함하지 않았으며 Python 환경에서 실행한다.

기존 HWPX·PDF는 `docs/design`, 개발 준비 문서는 `docs/development`, UML은 `docs/diagrams`, VPP 모델은 `models/visual-paradigm`으로 옮겼다. 문서의 “아직 구현하지 않았다”는 작성 당시 상태이며, 현재 구현과 시험 결과는 이 폴더의 기록을 따른다. 구조 정리 내역은 [구조 정리 검증](구조정리_검증.md), 전체 안내는 [Word 가이드](../ATM_프로젝트_구조및개발가이드.docx)를 참조한다. 교수 확인·외부 제출·GitHub 업로드는 수행하지 않았다.
