# 프로젝트 구조 정리 검증

## 변경 내용

제품 코드를 `src/atm_app` 아래의 domain, application, presentation, infrastructure, shared로 분리했다. 9개 클래스와 OP 44개의 기능 계약을 유지하고 import와 시드 경로를 수정했다.

기존 설계서는 `docs/design`, 개발 준비 자료는 `docs/development`, 실행 결과는 `docs/results`, UML 그림은 `docs/diagrams`, VPP 원본은 `models/visual-paradigm`으로 옮겼다. 문서 생성 도구는 `tools/docs`에 있다.

## 확인 결과

- 전체 제품 및 구조 회귀 자동 시험 68개 통과, 설계 시험 사례 37개 통과.
- `python run_atm.py --check`와 가상환경의 `python -m atm_app --check` 통과.
- 패키지 editable 설치와 wheel 빌드 성공.
- wheel을 별도 대상 폴더에 설치하고, 소스 경로 없이 격리 Python 프로세스에서 계좌 3개 로드와 정상 인증을 확인했다.
- 배포 패키지에 `infrastructure/data/accounts.seed.json`이 포함된 것을 확인했다.
- HWPX, 기존 PDF, 피드백, UML 그림과 VPP 및 원본 백업 47개 파일의 이동 전후 SHA256이 같다.
- 이동 전 소스와 문서 복사본 및 상세 이동 기록 27건은 `.artifacts/migration`에 보존했다.

## 실행 경로

설치 없이 `python run_atm.py` 또는 `ATM_실행.pyw`로 실행한다. `src` 구조에서 `python -m atm_app`을 사용할 때는 먼저 가상환경에 `pip install -e .`로 설치한다. 현재 README와 [Word 가이드](../ATM_프로젝트_구조및개발가이드.docx)에 정리했다.

## Git 추적 범위

`.artifacts`, `.venv`, 빌드 결과, Python 캐시, Word 잠금 파일, VPP 자동 백업을 `.gitignore`로 제외했다. 원본을 지운 것이 아니라 로컬 보관 위치와 저장소 관리 범위를 구분한 것이다. Git 저장소 초기화, 커밋, 푸시는 수행하지 않았다.

실제 제품 자동 실행 결과는 [테스트결과](테스트결과.md)를 참조한다. Word 문서는 Microsoft Word의 문서 API로 14쪽을 렌더링하고 전체 페이지의 표, 글자, 줄바꿈과 쪽번호를 검토했다. DOCX 내부 구조와 OP 44개 및 TC 37개 포함 여부, 문서 링크 71개도 검사했다. 검토용 PDF와 PNG는 `.artifacts`에 두며 제출 문서는 DOCX이다.
