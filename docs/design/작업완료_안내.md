# 상세설계서 보완 및 개발 준비 작업

> 이 문서는 설계서 보완 당시의 기록이다. 이후 ATM 앱을 구현했다. 현재 실행 방법은 [README](../../README.md), 구현 내용과 실제 자동 시험 결과는 [개발결과](../results/구현현황.md)를 참조한다.

2026-11-18 기준으로 `1116교수님피드백.txt`와 원본 설계서·다이어그램을 검토하여 통합 v3.0.0을 작성했다.

## 산출물

- [최종 상세설계서 HWPX](최종_SW공학_상세설계서_박교범_2023243047.hwpx): 기존 파일명으로 보완했다. 원래 파일은 확장자가 HWPX였으나 내부는 구형 HWP였으며, 보완본은 실제 HWPX ZIP/XML 형식이다.
- [검토용 PDF](ATM_상세설계서_최종보완_검토용.pdf): 39쪽. 클래스 그림은 32쪽 A3 가로 확대면이고 나머지는 A4다.
- [개발 준비 문서](../development/README.md): 개발환경·아키텍처·44개 메소드 계약·데이터 스키마·시드·37개 시험 사례·구현 순서·설계 결정·추적표·수동 검증 양식이다.
- [최종 UML 자료](../diagrams/최종보완): 문서에 사용한 8개 PNG, 수정 가능한 8개 SVG, UML 7개 PlantUML 원본이다. 아키텍처는 SVG를 편집한다.
- [편집용 본문](상세설계서_최종보완_원문.md): HWPX·PDF와 같은 내용의 Markdown이다.
- 원본 백업 (로컬 `.artifacts/originals`): 보완 전 바이너리를 실제 형식에 맞춰 `.hwp`로 보존했다. 기존 VPP·백업·7개 다이어그램 이미지는 수정하지 않았다.

## 반영 내용

요구사항을 규범 문장으로 다시 작성했다. 개념 객체를 재분류하고 상태도는 가상 계좌 한 개의 거래 가능·차단 상태를 대상으로 고쳤다. 요구사항→UC→FP→OP→TC의 도출 근거를 연결했다. 9개 클래스와 44개 메소드를 그림보다 앞에서 명세하고 클래스 그림을 3열로 정렬했다. 무관한 음악 엔진 예시·ID 오기·외부 액터 표현도 정리했다.

원래의 입출금·송신 계좌만 차감하는 가상 이체·화면 초기화 범위를 유지했다. 원문 미정 사항인 언어·계좌번호 형식·양수 입력·자료 유지 기간 등은 개발 기준안 D-01~07로 분리했다. 교수님의 추가 지시나 승인으로 표시하지 않았다.

## 검증과 제한

HWPX의 ZIP·XML·스키마·스타일 참조·이미지·메소드·요구사항 연결을 검사했다. PDF 39쪽을 모두 PNG로 렌더링하여 전체 배치와 주요 상세면을 확인했다. 문서 검증 기록은 검증결과 (로컬 `.artifacts/analysis/검증결과.json`), 재생성 도구는 `tools/`에 있다.

이 환경의 한글 프로그램 화면 제어 연결이 작동하지 않아 **한글에서 직접 열었을 때의 줄바꿈·쪽수·인쇄 배치는 확인하지 못했다.** PDF는 HWPX의 한글 내보내기가 아니라 동일 내용을 별도로 조판한 검토본이다. 한글 버전·글꼴에 따라 배치가 달라질 수 있다. 제출 직전에는 한글에서 HWPX의 쪽 나눔과 A3 확대면을 확인한다.

이번 작업은 문서와 개발 준비 자료 작성이다. 제품 GUI·업무 코드를 구현하거나 제품 시험을 실행하지 않았다. 37개 시험 사례의 상태는 모두 NOT_RUN이며 실제 결과는 개발 후 기록한다.
