# 설계 결정과 변경 관리

원문에 없는 경계 규칙과 구현 기준안을 명시한다. 교수님이 지시하거나 승인한 내용으로 간주하지 않는다.

| ID | 주제 | 채택 기준 |
| --- | --- | --- |
| D-01 | 구현 기준 | Python 3.13, Tkinter/ttk, unittest, 표준 json 모듈을 사용한다. 기존 구현 언어가 정해진 자료는 없으므로 개발 준비를 위한 기준안으로 채택한다. |
| D-02 | 계좌·금액 입력 | 가상 계좌번호는 ASCII 숫자 12자리 문자열로 통일한다. PIN은 숫자 4자리 문자열로 보존한다. 금액은 ASCII 숫자 1~10자리이고 값이 1 이상이어야 한다. 자동 공백 제거·쉼표 해석은 하지 않는다. |
| D-03 | 인증 오류 | 형식 오류와 미등록 계좌는 오류 횟수를 늘리지 않는다. 등록된 미차단 계좌의 PIN 불일치만 증가시킨다. 성공하면 0으로 초기화하고, 5회째부터 blocked=true로 고정한다. |
| D-04 | 가상 이체 | 원문 범위대로 송신 계좌만 차감한다. 수신 계좌의 등록 여부 확인·입금·실제 송금·수수료는 구현하지 않는다. 12자리 형식과 본인 계좌 여부만 확인한다. 이체의 별도 100만 원 한도는 두지 않는다. |
| D-05 | 자료 유지 기간 | 계좌 잔액·오류 횟수·차단 상태는 실행 중 메모리에 유지한다. 로그아웃으로 계좌 데이터는 초기화하지 않는다. 앱 재시작 시 시드로 복구된다. 재시작 이후 영속 저장과 차단 해제 UI는 현 범위 밖이다. |
| D-06 | 거래 종료 | 거래 결과 뒤 “계속 이용”을 선택하면 메뉴로, “종료”를 선택하면 로그인으로 이동한다. 입력 취소는 잔액 변경 없이 메뉴로 돌아간다. 명세표는 안내만 제공하며 프린터 동작은 없다. |
| D-07 | 중복 처리·예외 | UI는 처리 중 확인 버튼을 비활성화한다. AccountManager도 거래 규칙을 다시 검사한다. 승인 전에는 잔액을 바꾸지 않으며 실패 시 기존 잔액을 유지한다. 잔액 상한은 9,999,999,999원으로 둔다. |

## 원문 보존과 보완 구분

원문 보존: 계좌번호+4자리 PIN 인증, 5회 오류 차단, 즉시 잔액, 100만 원 입금·출금, 1만 원 출금 단위, 송신만 차감하는 가상 이체, 종료 시 화면 정리, 9개 클래스.

보완 결정: 구체적 계좌번호 길이, ASCII 입력과 양수·잔액 상한, 미등록·형식 오류의 횟수 규칙, 본인 이체 거절, 연속 거래 선택, 메모리 유지 기간, Python/Tkinter 기준, 중복 클릭·오류 방어.

## 변경 절차

1. 변경 사유와 대상 D/REQ를 기록한다.
2. UC와 FP 단계, OP 입출력, 속성·관계, 상태도·시퀀스, 데이터 스키마, 시험 사례의 영향을 찾는다.
3. 관련 문서와 코드 변경을 같은 작업으로 묶고 기준 버전을 올린다.
4. 영향 시험을 다시 실행하고 결과를 기록한다.
