# 메소드 인터페이스 계약

설계 명칭과 Python 구현 이름을 연결한다. 모든 메소드는 앞선 FP 처리 단계에서 도출한다. 공개/내부 구분과 원문 9개 클래스를 유지한다. String→str, int→int, boolean→bool, void→None, null→None으로 대응한다. 금액 매개변수에는 bool을 허용하지 않는다.

## TransactionScreen

전체 거래 흐름을 조정하는 제어 객체.

| 속성 | 설계 형식 | 설명 |
| --- | --- | --- |
| screenData | ScreenData | 현재 세션 정보 1개 |
| accountManager | AccountManager | 공유 계좌 서비스 1개 |
| processing | boolean | 거래 콜백 재진입 방지; 초기값 false |

### OP-01 로그인요청

- 구현 이름: `TransactionScreen.request_login`
- 입력: `accountNumber: String, password: String`
- 반환: `void`
- 처리: 형식 검사 후 로그인확인을 호출한다. 성공하면 계좌번호를 저장하고 잔액을 갱신한다. 실패 시 경고하며 5회 차단이면 거래종료를 호출한다.
- 도출: FP-01.2~05 / REQ-LOGIN-01~03

### OP-02 거래메뉴선택

- 구현 이름: `TransactionScreen.select_menu`
- 입력: `menu: String`
- 반환: `void`
- 처리: 인증 상태를 확인하고 입금·출금·이체 입력 화면 또는 종료 동작을 선택한다. 잘못된 메뉴는 거절한다.
- 도출: FP-02~05.1 / REQ-BANK-02,05,09; REQ-SYS-01

### OP-03 입금요청

- 구현 이름: `TransactionScreen.request_deposit`
- 입력: `amountText: String`
- 반환: `void`
- 처리: 입금 형식·한도 검사, 진행 안내, AccountManager 호출, 결과 표시와 화면잔액갱신을 순서대로 수행한다.
- 도출: FP-02.2~04 / REQ-BANK-02~04

### OP-04 출금요청

- 구현 이름: `TransactionScreen.request_withdrawal`
- 입력: `amountText: String`
- 반환: `void`
- 처리: 공통 금액 형식, 출금 단위·한도를 확인하고 출금을 요청한다. 성공 시 잔액과 완료·명세표 안내를 갱신한다.
- 도출: FP-03.2~05 / REQ-BANK-05~08

### OP-05 가상이체요청

- 구현 이름: `TransactionScreen.request_transfer`
- 입력: `targetAccountNumber: String, amountText: String`
- 반환: `void`
- 처리: 대상 형식·본인 여부·양의 정수 금액을 검사하고 가상이체처리를 요청한다. 성공 시 새 잔액과 완료를 표시한다.
- 도출: FP-04.2~05 / REQ-BANK-09~11

### OP-06 거래종료

- 구현 이름: `TransactionScreen.end_session`
- 입력: `없음`
- 반환: `void`
- 처리: 활성 거래 처리가 끝난 뒤 화면정보지우기와 모든 입력 위젯 초기화를 수행하고 로그인화면표시를 호출한다.
- 도출: FP-05.1~03 / REQ-SYS-01

### OP-07 화면잔액갱신

- 구현 이름: `TransactionScreen._refresh_balance`
- 입력: `없음`
- 반환: `void`
- 처리: 현재 계좌번호로 계좌잔액조회를 호출하고 표시잔액저장 후 잔액과메뉴표시를 호출한다. 미인증 상태이면 조회하지 않는다.
- 도출: FP-01.5; FP-02~04.5 / REQ-BANK-01

## LoginScreen

로그인 입력과 경고를 담당하는 경계 객체.

### OP-08 로그인화면표시

- 구현 이름: `LoginScreen.show`
- 입력: `없음`
- 반환: `void`
- 처리: 빈 계좌번호·PIN 입력란을 표시한다. PIN은 마스킹한다.
- 도출: FP-01.1; FP-05.3 / REQ-LOGIN-01; REQ-SYS-01

### OP-09 비밀번호형식확인

- 구현 이름: `LoginScreen.validate_pin`
- 입력: `password: String`
- 반환: `boolean`
- 처리: 정규식 [0-9]{4} 전체 일치일 때만 true이다. 0123은 유효하다. 형식 오류는 계좌 오류 횟수를 바꾸지 않는다.
- 도출: FP-01.2 / REQ-LOGIN-02

### OP-10 로그인경고표시

- 구현 이름: `LoginScreen.show_warning`
- 입력: `message: String`
- 반환: `void`
- 처리: 반환 코드에 해당하는 형식 오류·인증 실패·거래 차단 문구를 표시하고 PIN 입력란을 비운다.
- 도출: FP-01.2~04 / REQ-LOGIN-02~03

## MenuScreen

잔액과 거래 메뉴를 표시하는 경계 객체.

### OP-11 잔액과메뉴표시

- 구현 이름: `MenuScreen.show`
- 입력: `balance: int`
- 반환: `void`
- 처리: 원 단위 잔액과 입금·출금·이체·종료 버튼을 표시한다. 거래 후 메뉴 복귀 시 최신 값을 표시한다.
- 도출: FP-01.5; FP-02~04.5 / REQ-BANK-01

## ScreenData

한 세션의 표시 정보만 보유하는 정보 객체.

| 속성 | 설계 형식 | 설명 |
| --- | --- | --- |
| accountNumber | String \| null | 인증 후 설정, 초기값 null |
| shownBalance | int \| null | 화면용 사본, 초기값 null |
| selectedMenu | String \| null | 초기값 null |
| amountText | String | 초기값 빈 문자열 |
| targetAccountNumber | String | 초기값 빈 문자열 |

### OP-24 계좌번호저장

- 구현 이름: `ScreenData.set_account_number`
- 입력: `accountNumber: String`
- 반환: `void`
- 처리: 인증에 성공한 가상 계좌번호만 저장한다.
- 도출: FP-01.5 / REQ-LOGIN-01

### OP-25 계좌번호읽기

- 구현 이름: `ScreenData.get_account_number`
- 입력: `없음`
- 반환: `String | null`
- 처리: 현재 인증 계좌번호를 반환한다. null이면 비인증 세션이다.
- 도출: FP-02~04.3 / REQ-LOGIN-01; REQ-Q-01

### OP-26 표시잔액저장

- 구현 이름: `ScreenData.set_shown_balance`
- 입력: `balance: int`
- 반환: `void`
- 처리: AccountManager에서 읽은 잔액을 화면 사본으로 저장한다. 이 값으로 출금 승인을 결정하지 않는다.
- 도출: FP-01.5; FP-02~04.5 / REQ-BANK-01

### OP-27 거래입력정보저장

- 구현 이름: `ScreenData.set_transaction_input`
- 입력: `menu: String, amountText: String, targetAccountNumber: String`
- 반환: `void`
- 처리: 현재 거래의 메뉴와 원문 금액, 대상 번호를 임시 저장한다. PIN은 저장하지 않는다.
- 도출: FP-02~04.1 / REQ-BANK-02,05,09

### OP-28 화면정보지우기

- 구현 이름: `ScreenData.clear`
- 입력: `없음`
- 반환: `void`
- 처리: 다섯 속성을 초기값으로 되돌린다. 계좌의 잔액·오류 횟수·차단 상태는 수정하지 않는다.
- 도출: FP-05.2 / REQ-SYS-01

## AccountManager

계좌 조회·인증·업무 검증을 담당하는 제어 객체.

| 속성 | 설계 형식 | 설명 |
| --- | --- | --- |
| accounts | List<VirtualAccount> | 앱 시작 시 검증된 시드에서 로드한 목록 |

### OP-29 가상계좌찾기

- 구현 이름: `AccountManager._find_account`
- 입력: `accountNumber: String`
- 반환: `VirtualAccount | null`
- 처리: 계좌번호가 일치하는 단일 계좌를 반환한다. 미등록 계좌이면 null이며 잔액 조회/거래는 허용하지 않는다.
- 도출: FP-01.3; FP-02~04.3 / REQ-LOGIN-01

### OP-30 비밀번호오류처리

- 구현 이름: `AccountManager._handle_failed_pin`
- 입력: `account: VirtualAccount`
- 반환: `void`
- 처리: 오류횟수늘리기 결과가 5이면 계좌거래차단을 호출한다. 이미 차단된 계좌에는 다시 증가시키지 않는다.
- 도출: FP-01.4 / REQ-LOGIN-03

### OP-31 로그인확인

- 구현 이름: `AccountManager.authenticate`
- 입력: `accountNumber: String, password: String`
- 반환: `String`
- 처리: 형식·등록·차단 여부를 확인한다. PIN 일치 시 오류횟수초기화 후 SUCCESS, 불일치 시 INVALID_CREDENTIALS 또는 ACCOUNT_BLOCKED를 반환한다.
- 도출: FP-01.2~04 / REQ-LOGIN-01~03

### OP-32 계좌잔액조회

- 구현 이름: `AccountManager.get_balance`
- 입력: `accountNumber: String`
- 반환: `int`
- 처리: 등록된 미차단 계좌의 잔액을 반환한다. 잘못된 요청은 명시적 업무 오류를 발생시키며 0원으로 위장하지 않는다.
- 도출: FP-01.5; FP-02~04.3 / REQ-BANK-01,07,10

### OP-33 입금처리

- 구현 이름: `AccountManager.deposit`
- 입력: `accountNumber: String, amount: int`
- 반환: `boolean`
- 처리: 미차단 계좌, 정수형 양수, 100만 원 한도, 잔액 상한을 재검사한 뒤 잔액더하기를 한 번 호출한다. 실패하면 false이고 무변경이다.
- 도출: FP-02.3 / REQ-BANK-02~04; REQ-Q-03

### OP-34 출금처리

- 구현 이름: `AccountManager.withdraw`
- 입력: `accountNumber: String, amount: int`
- 반환: `boolean`
- 처리: 정수형 양수·1만 원 단위·100만 원 한도·실제 잔액·차단 여부를 다시 확인한 뒤 잔액빼기를 한 번 호출한다.
- 도출: FP-03.3~04 / REQ-BANK-05~08

### OP-35 가상이체처리

- 구현 이름: `AccountManager.transfer`
- 입력: `fromAccountNumber: String, targetAccountNumber: String, amount: int`
- 반환: `boolean`
- 처리: 대상 12자리·본인 제외·정수형 양수·실제 잔액·차단 여부를 재검사한다. 송신 계좌에서만 한 번 차감하며 대상 계좌는 생성·변경하지 않는다.
- 도출: FP-04.2~04 / REQ-BANK-09~11

## VirtualAccount

가상 계좌 한 개의 지속되는 도메인 상태.

| 속성 | 설계 형식 | 설명 |
| --- | --- | --- |
| accountNumber | String | 고유한 ASCII 숫자 12자리, 변경 금지 |
| password | String | 가상 PIN ASCII 숫자 4자리 |
| balance | int | 0~9,999,999,999 |
| failedCount | int | 0~5, 초기값 0 |
| blocked | boolean | failedCount=5와 동치, 초기값 false |

### OP-36 계좌번호읽기

- 구현 이름: `VirtualAccount.get_account_number`
- 입력: `없음`
- 반환: `String`
- 처리: 자신의 고유 계좌번호를 반환한다.
- 도출: FP-01.3 / REQ-LOGIN-01

### OP-37 비밀번호일치확인

- 구현 이름: `VirtualAccount.matches_pin`
- 입력: `password: String`
- 반환: `boolean`
- 처리: 입력 PIN과 가상 PIN의 문자열 일치 여부를 반환한다. 숫자로 변환하지 않는다.
- 도출: FP-01.3 / REQ-LOGIN-01~02

### OP-38 잔액읽기

- 구현 이름: `VirtualAccount.get_balance`
- 입력: `없음`
- 반환: `int`
- 처리: 현재 계좌 잔액을 반환한다.
- 도출: FP-01.5; FP-02~04.3 / REQ-BANK-01,07,10

### OP-39 잔액더하기

- 구현 이름: `VirtualAccount.credit`
- 입력: `amount: int`
- 반환: `void`
- 처리: 검사된 양수를 잔액에 더한다. 음수·상한 초과·차단이면 변경 전 거절한다.
- 도출: FP-02.3 / REQ-BANK-04

### OP-40 잔액빼기

- 구현 이름: `VirtualAccount.debit`
- 입력: `amount: int`

## 공통 함수 및 오류 계약

`validation.parse_amount(text: str) -> int`는 [0-9]{1,10} 전체 일치 후 1 이상인지 검사한다. 유효하지 않으면 INVALID_AMOUNT 업무 오류를 반환하거나 지정 예외를 발생시킨다. 쉼표·공백·부호·소수·비ASCII 숫자를 허용하지 않는다. 거래별 한도 검사는 호출자가 별도로 한다.

`validation.validate_account_number(text: str) -> bool`은 [0-9]{12} 전체 일치 여부를 반환한다. 이체 대상 존재 여부를 확인하지 않는다.

`bootstrap.load_seed(path) -> list[VirtualAccount]`는 UTF-8 JSON을 전체 검증한 뒤 객체 목록을 구성한다. `bootstrap.validate_seed(data) -> None`은 스키마와 계좌번호 유일성, blocked==(failedCount==5)를 검증하고 오류이면 예외를 발생시킨다. 시드에 쓰지 않는다.

로그인확인은 SUCCESS, INVALID_FORMAT, INVALID_CREDENTIALS, ACCOUNT_BLOCKED 문자열 중 하나를 반환한다. 미등록 계좌와 PIN 불일치는 INVALID_CREDENTIALS이지만, 오류 횟수 증가는 등록된 미차단 계좌의 PIN 불일치에서만 일어난다.

계좌잔액조회는 존재하지 않거나 차단된 계좌이면 `AccountAccessError`를 발생시킨다. 제어기는 이를 받아 성공 안내 없이 세션을 정리한다. 정상 잔액 0과 조회 오류를 혼동하지 않는다.

입금처리·출금처리·가상이체처리는 원문 계약에 맞춰 bool을 반환한다. false는 무변경이며, 제어기가 앞선 입력 검사로 구체적인 이유를 안내한다. 재검사에서 거절된 경우에는 일반 처리 불가 문구를 사용한다. 예상하지 못한 예외는 false로 조용히 삼키지 않고 제어기 예외 경계에서 성공 표시를 막고 세션을 정리한다. 예외 정보에 PIN을 기록하지 않는다.

서비스는 인증 상태를 보유하지 않는다. 사용자 세션 허용 여부는 TransactionScreen이 확인하고, AccountManager는 전달받은 계좌의 존재·차단·업무 규칙을 검사한다. GUI에서 서비스로 들어오는 정상 경로에는 항상 인증된 ScreenData.accountNumber만 전달한다. 서비스 자체의 임의 호출까지 인증을 강제하려면 향후 명시적 세션 토큰 계약을 추가해야 한다.
