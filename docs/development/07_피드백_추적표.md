# 피드백 반영과 추적성

자료: 루트의 `1116교수님피드백.txt`, 11/13 원본 상세설계서, 기존 다이어그램. 피드백 파일의 중복 번호를 내용 순서에 따라 FB-01~05로 정규화했다.

| 피드백 | 반영 | 확인 방법 |
| --- | --- | --- |
| FB-01 요구사항은 문장 | REQ 15개와 보완 품질 5개를 조건·주어·의무 동작으로 기술 | I장과 아래 요구사항 목록 |
| FB-02 상태도 개념 객체 | VirtualAccount 한 개의 거래 가능/차단 상태로 재설계 | IV-1~3, state_account SVG/PNG/PUML |
| FB-03 워크플로우 근거 | 요구사항→UC→FP 단계→OP→시험 연결 | II장 기능 프로세스, III장 OP 근거 |
| FB-04 클래스 그림 정렬 | 3열 고정 폭·일정 간격 새 UML | class_full SVG/PNG/PUML |
| FB-05 메소드 선행 명세 | 44개 OP의 이름·매개변수·반환·행위·도출근거를 그림 앞에 배치 | III장, interface_catalog.json |

원문의 무관한 음악 엔진 예시를 ATM 구조로 교체했다. 시스템 내부 객체를 외부 액터로 취급한 표현을 정리하고, 기존 하위 UC를 FP 단계로 통합했다. 클래스와 계좌 범위는 보존했으며 변경 기준은 D-01~07에 명시했다.

## 요구사항→유즈케이스→기능 단계

| 요구사항 | 규범 문장 | UC | FP |
| --- | --- | --- | --- |
| REQ-LOGIN-01 | 시스템은 초기 화면에서 가상 계좌번호와 비밀번호를 입력받고, 등록된 계좌의 인증에 성공한 사용자에게만 거래 메뉴를 제공해야 한다. | UC-01 | FP-01 |
| REQ-LOGIN-02 | 시스템은 비밀번호를 ASCII 숫자 4자리의 문자열로 검사해야 하며, 빈 문자열·문자·길이 오류가 있으면 비밀번호를 비교하지 않고 재입력을 안내해야 한다. | UC-01 | FP-01.2 |
| REQ-LOGIN-03 | 시스템은 등록된 미차단 계좌의 비밀번호가 불일치할 때마다 연속 오류 횟수를 1회 증가시키고, 5회째에는 해당 계좌의 거래를 차단하고 임시 화면 정보를 지운 뒤 초기 로그인 화면을 표시해야 한다. | UC-01 | FP-01.4 |
| REQ-BANK-01 | 시스템은 로그인 성공 직후 현재 가상 계좌의 잔액을 거래 메뉴 화면에 표시하고, 거래 성공 후에도 변경된 잔액으로 화면을 갱신해야 한다. | UC-01~04 | FP-01.5 |
| REQ-BANK-02 | 시스템은 입금액을 ASCII 숫자로 구성된 양의 정수로 검사하고, 빈 값·0·음수·소수·공백·문자가 포함된 입력이면 이유를 안내하고 해당 입금을 취소해야 한다. | UC-02 | FP-02.2 |
| REQ-BANK-03 | 시스템은 1회 입금액을 1,000,000원 이하로 제한하고, 이를 초과하면 잔액을 변경하지 않고 한도 초과를 안내해야 한다. | UC-02 | FP-02.2 |
| REQ-BANK-04 | 시스템은 입금 조건을 모두 통과하면 “입금 중입니다.”를 표시하고, 입금액을 해당 계좌 잔액에 한 번만 더한 뒤 완료 결과와 새 잔액을 표시해야 한다. | UC-02 | FP-02.3~04 |
| REQ-BANK-05 | 시스템은 출금액을 0보다 큰 10,000원의 배수로 제한하고, 입력 형식 또는 단위가 맞지 않으면 출금을 취소하고 오류를 안내해야 한다. | UC-03 | FP-03.2 |
| REQ-BANK-06 | 시스템은 1회 출금액을 1,000,000원 이하로 제한하고, 이를 초과하면 잔액을 변경하지 않고 한도 초과를 안내해야 한다. | UC-03 | FP-03.2 |
| REQ-BANK-07 | 시스템은 출금 직전에 현재 계좌의 실제 잔액을 확인하고, 출금액이 잔액보다 크면 “잔액이 부족합니다.”를 표시하고 출금을 취소해야 한다. | UC-03 | FP-03.3 |
| REQ-BANK-08 | 시스템은 출금 조건을 모두 통과하면 계좌 잔액에서 출금액을 한 번만 차감하고, 새 잔액과 출금 완료 결과 및 명세표 출력 여부 안내를 표시해야 한다. | UC-03 | FP-03.4~05 |
| REQ-BANK-09 | 시스템은 가상 이체 대상 계좌번호와 양의 정수 송금액을 입력받고, 대상 계좌번호가 설계 형식에 맞지 않거나 본인 계좌이면 이체를 취소하고 오류를 안내해야 한다. | UC-04 | FP-04.1~02 |
| REQ-BANK-10 | 시스템은 가상 이체 직전에 송신 계좌의 실제 잔액을 확인하고, 송금액이 잔액보다 크면 잔액 부족을 안내하고 이체를 취소해야 한다. | UC-04 | FP-04.3 |
| REQ-BANK-11 | 시스템은 가상 이체 조건을 모두 통과하면 송신 가상 계좌의 잔액에서 송금액을 한 번만 차감하고, “이체가 완료되었습니다.”와 새 잔액을 표시해야 한다. | UC-04 | FP-04.4~05 |
| REQ-SYS-01 | 시스템은 사용자가 종료를 선택하거나 거래 후 계속 이용하지 않겠다고 선택하면 계좌번호·잔액·거래 입력값·비밀번호 입력란 등 세션 정보를 지우고 초기 로그인 화면을 표시해야 한다. | UC-05 | FP-05 |

## 품질 보완

| REQ-Q-01 | 시스템은 인증된 세션이 없거나 계좌가 차단된 상태에서 거래 제어기에 입금·출금·이체 요청이 들어오면 요청을 거절하고 잔액을 유지해야 한다. |

| REQ-Q-03 | 시스템은 업무 오류나 예상하지 못한 예외가 발생하면 성공 문구를 표시하지 않고, 승인되지 않은 거래의 잔액을 유지해야 한다. |
| REQ-Q-04 | 시스템은 로그인 화면에서 PIN을 마스킹하고 PIN을 ScreenData나 로그에 보관하지 않아야 한다. 실계좌·실비밀번호를 사용하지 않는다. |
| REQ-Q-05 | 시스템은 잘못된 초기 데이터의 중복 계좌번호·음수 잔액·오류 횟수/차단 불일치를 발견하면 거래 화면을 제공하지 않고 데이터 오류를 안내해야 한다. |

메소드별 추적은 02 인터페이스 계약, 시험별 추적은 04 테스트 계획을 참조한다. 제품 구현의 통과 여부는 아직 확인하지 않았다.
